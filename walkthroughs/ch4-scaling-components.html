✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • Picture an order at a kitchen pass. The waiter (kubectl) hands a ticket to the front desk (API server), which files it (etcd). The head chef (controller manager) sees the ticket says 'five dishes, only three made' and queues two more. The expediter (scheduler) assigns each to a station (node), and the cooks (kubelets) cook.
  • Nothing talks to anything directly. Every component watches the API server and reacts to changes, which is why the system recovers cleanly if one piece restarts.
  • Apply the fix command (step 3), then verify (step 4).
  • Confirm status becomes Running.

Key points

  • API server is the single front door; etcd stores the intent
  • Controller manager reconciles replica counts
  • Scheduler only chooses a node; it does not start containers
  • Kubelet on the chosen node pulls images and runs the Pod
