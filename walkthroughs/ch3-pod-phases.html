What are the Pod phases, and how does the phase help you troubleshoot?

Chapter 3 junior walkthrough · 4 steps
Say first

A Pod is always in one of five phases: Pending, Running, Succeeded, Failed or Unknown. The phase tells you which stage to investigate first: scheduling and image pull, a live container, a clean exit, a failure, or a lost node.

⚠ Predicted failure

  • Pitfall: Calling CrashLoopBackOff or ImagePullBackOff a phase.
  • Pitfall: Assuming Running means the app is healthy and serving.
  • If ignored, this surfaces as: Progressing.

✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • Pending means the API server accepted the Pod but it is not running yet: the scheduler may still be finding a node, or the node is pulling images.
  • Running means the Pod is bound to a node and at least one container is running or starting or restarting.
  • Succeeded and Failed are terminal: every container has stopped, and Failed means at least one stopped with a nonzero exit code or was killed.
  • Apply the fix command (step 3), then verify (step 4).
  • Confirm status becomes Available.

Explain

  • Pending means the API server accepted the Pod but it is not running yet: the scheduler may still be finding a node, or the node is pulling images.
  • Running means the Pod is bound to a node and at least one container is running or starting or restarting.
  • Succeeded and Failed are terminal: every container has stopped, and Failed means at least one stopped with a nonzero exit code or was killed.
  • Unknown usually means the control plane cannot reach the node, so nobody can report the Pod's state.

Key points

  • Phase is a coarse summary; container states give the detail.
  • Pending for a long time points to scheduling or image problems.
  • Succeeded and Failed are final for run-to-completion Pods.
  • Unknown is almost always a node communication issue.
  • CrashLoopBackOff is a container status, not a phase.
