A Pod is in CrashLoopBackOff. How do you debug it, including when there are no logs?

Chapter 16 mid walkthrough · 4 steps
Say first

CrashLoopBackOff means the container starts, exits, and the kubelet restarts it with growing delays. I read the last state and exit code from describe, then the previous container's logs, and if there are none I debug a copy of the Pod with a shell.

⚠ Predicted failure

  • Pitfall: Reading current logs of a container that just restarted and seeing nothing.
  • Pitfall: Forgetting the debug Pod exists after the investigation.
  • If ignored, this surfaces as: CrashLoopBackOff.

✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • Like a car that starts, stalls and is restarted with a longer wait each time, the status is a waiting state, not the error. The error is whatever made the process exit.
  • Step 1, kubectl describe pod: look at Last State for the terminated container, its reason and exit code. Step 2, kubectl logs POD --previous, because the current container may be too new to have output. Step 3, map the evidence to a cause: application bug, missing config or mount, OOM kill, or a liveness probe killing a healthy but slow app.
  • If the process dies before printing anything, use kubectl debug with --copy-to to run a clone with a shell instead of the real command. There you can list files, check environment variables and run the binary by hand. The copy is a real Pod, so delete it afterwards.
  • Apply the fix command (step 3), then verify (step 4).
  • Confirm status becomes Running.

Key points

  • CrashLoopBackOff is a symptom; the exit code and previous logs are the evidence.
  • Exit 1 usually means an application error; 137 means SIGKILL, often an OOM kill.
  • Always use --previous to read the crashed instance's logs.
  • A liveness probe failure event means the kubelet killed the container.
  • kubectl debug --copy-to leaves a Pod behind; clean it up.

Commands

CommandWhat it shows
kubectl describe pod broken-appLast State, Reason, Exit Code and probe events
kubectl logs broken-app --previousLogs of the last crashed container instance
kubectl debug -it broken-app --copy-to=broken-app-debug --container=app -- shRun a copy of the Pod with a shell instead of the crashing command
kubectl delete pod broken-app-debugRemove the debug copy when finished
