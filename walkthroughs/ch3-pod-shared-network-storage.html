What do containers in the same Pod share, and what is emptyDir used for?

Chapter 3 junior walkthrough · 4 steps
Say first

They share one IP address, one port space and any volumes the Pod declares, so they reach each other over localhost and can exchange files through a common volume such as emptyDir.

✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • Because the network namespace is shared, a sidecar can call the app on localhost:8080 with no service discovery. The flip side is that two containers in one Pod cannot both listen on the same port.
  • Volumes are declared once at Pod level, then each container mounts them wherever it likes. An emptyDir starts empty when the Pod is placed on a node and is wiped when the Pod leaves that node. It survives container restarts, though.
  • Classic example: one container writes a file every second into an emptyDir, and an nginx container serves that same directory, so a browser refresh always shows fresh content.

Explain

  • Because the network namespace is shared, a sidecar can call the app on localhost:8080 with no service discovery. The flip side is that two containers in one Pod cannot both listen on the same port.
  • Volumes are declared once at Pod level, then each container mounts them wherever it likes. An emptyDir starts empty when the Pod is placed on a node and is wiped when the Pod leaves that node. It survives container restarts, though.
  • Classic example: one container writes a file every second into an emptyDir, and an nginx container serves that same directory, so a browser refresh always shows fresh content.

Key points

  • emptyDir lifetime equals the Pod's lifetime on that node, not the container's.
  • Useful for scratch space, caches and handing files between containers.
  • It is not durable storage; use a PersistentVolume for data that must survive.
  • Shared IP means port clashes are possible between containers.
