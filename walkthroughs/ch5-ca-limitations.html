What are the limitations of the Cluster Autoscaler?

Chapter 5 senior walkthrough · 4 steps
Say first

It is reactive, bound to pre-defined node groups, driven by requests rather than real usage, and limited by how fast the cloud can boot machines.

⚠ Predicted failure

  • Pitfall: Running the CA and Karpenter over the same node set; one adds a node while the other removes it.
  • If ignored, this surfaces as: Unknown.

✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • Because it only acts after the scheduler fails, there is always a delay of a few minutes while the VM is provisioned. Spiky traffic can outrun it.
  • Because it grows predefined groups, you must decide instance types in advance and manage many groups for different needs. And since it reasons about Pod requests, over-generous requests lead to over-provisioning.
  • It also assumes Pods can be restarted elsewhere, so disruption-sensitive apps need PodDisruptionBudgets or annotations. On-premises support is weaker, and very large clusters can make it slow, though trimming node groups or giving it more resources helps.
  • Apply the fix command (step 3), then verify (step 4).
  • Confirm status becomes Healthy.

Explain

  • Because it only acts after the scheduler fails, there is always a delay of a few minutes while the VM is provisioned. Spiky traffic can outrun it.
  • Because it grows predefined groups, you must decide instance types in advance and manage many groups for different needs. And since it reasons about Pod requests, over-generous requests lead to over-provisioning.
  • It also assumes Pods can be restarted elsewhere, so disruption-sensitive apps need PodDisruptionBudgets or annotations. On-premises support is weaker, and very large clusters can make it slow, though trimming node groups or giving it more resources helps.

Key points

  • Scaling is reactive and not instant.
  • Node shapes are fixed by node groups chosen in advance.
  • Request-based, so inflated requests mean wasted nodes.
  • Never run it and another node autoscaler over the same nodes.
