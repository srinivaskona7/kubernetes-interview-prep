⚠ Predicted failure

  • Pitfall: Restarting CoreDNS before checking whether traffic can reach it.
  • If ignored, this surfaces as: CrashLoopBackOff.

✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • DNS is the cluster's phone book. If it fails, every app that uses names fails, even though Pods and Services are fine, so the blast radius is wide and the first job is to prove it is DNS.
  • Start inside the cluster: run a throwaway Pod with nslookup against a Service name and against an external name. If internal names fail, check kubectl get pods -n kube-system -l k8s-app=kube-dns and their logs; a bad Corefile ConfigMap often shows up here. Then confirm the kube-dns Service has a ClusterIP and endpoints.
  • If CoreDNS is healthy but queries time out, suspect a NetworkPolicy that denies egress on port 53 from the client namespace, or a node-level network problem. Also check the Pod's /etc/resolv.conf and its dnsPolicy, and remember that short names rely on search domains and ndots.
  • Apply the fix command (step 3), then verify (step 4).
  • Confirm status becomes Running.

Explain

  • DNS is the cluster's phone book. If it fails, every app that uses names fails, even though Pods and Services are fine, so the blast radius is wide and the first job is to prove it is DNS.
  • Start inside the cluster: run a throwaway Pod with nslookup against a Service name and against an external name. If internal names fail, check kubectl get pods -n kube-system -l k8s-app=kube-dns and their logs; a bad Corefile ConfigMap often shows up here. Then confirm the kube-dns Service has a ClusterIP and endpoints.
  • If CoreDNS is healthy but queries time out, suspect a NetworkPolicy that denies egress on port 53 from the client namespace, or a node-level network problem. Also check the Pod's /etc/resolv.conf and its dnsPolicy, and remember that short names rely on search domains and ndots.

Key points

  • Test from inside a Pod; your laptop's DNS tells you nothing.
  • Internal names resolve to ClusterIPs; external names are forwarded upstream.
  • A timeout usually means blocked or dead; NXDOMAIN means the name does not exist.
  • CoreDNS is normally labelled k8s-app=kube-dns, and its Service is still called kube-dns.
  • Restrictive egress policies must allow DNS.
