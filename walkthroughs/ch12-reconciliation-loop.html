⚠ Predicted failure

  • Pitfall: Writing edge-triggered logic that breaks if an event is missed.
  • Pitfall: Updating spec instead of status from the controller.
  • If ignored, this surfaces as: NotEstablished.

✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • Picture a thermostat: it reads the target temperature, measures the room, and heats or cools until they match, then keeps watching. The Operator does the same with Deployments, Services and ConfigMaps.
  • A watch event wakes the controller. It reads the spec, observes the current state, and if they differ it creates, patches or deletes child objects. It then updates status so users can see progress, and waits for the next event.
  • Good reconcilers are idempotent: running them twice causes no extra change. They are level-based, reacting to the state they find, not to the particular event that arrived.
  • Apply the fix command (step 3), then verify (step 4).
  • Confirm status becomes Established.

Explain

  • Picture a thermostat: it reads the target temperature, measures the room, and heats or cools until they match, then keeps watching. The Operator does the same with Deployments, Services and ConfigMaps.
  • A watch event wakes the controller. It reads the spec, observes the current state, and if they differ it creates, patches or deletes child objects. It then updates status so users can see progress, and waits for the next event.
  • Good reconcilers are idempotent: running them twice causes no extra change. They are level-based, reacting to the state they find, not to the particular event that arrived.

Key points

  • Triggered by watch events and periodic resyncs.
  • Must be idempotent and safe to retry.
  • Writes status separately from spec.
  • Child objects carry an owner reference so deleting the CR cleans them up.
  • Errors requeue the work with backoff.
