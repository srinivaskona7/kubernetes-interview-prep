You hit a question you cannot answer. What do you do?

Chapter 17 mid walkthrough · 4 steps
Say first

I say what I do know, state my assumptions, then reason toward an answer out loud and name how I would verify it. Thinking aloud shows method; silence or bluffing shows nothing.

⚠ Predicted failure

  • Pitfall: Bluffing about a command you are unsure of.
  • Pitfall: Going quiet while you think; narrate instead.
  • If ignored, this surfaces as: ImagePullBackOff.

✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • Think of a navigator with no GPS. Saying 'I'm not certain of the exact flag, but here is how I would find it' still gets you to the destination and is trusted.
  • A simple loop: restate the symptom, give two or three ranked hypotheses, pick one check, say what each result would mean, then summarise the cause, fix and prevention.
  • If you are missing a fact, be honest in one short sentence, then show adjacent knowledge: which object owns it, which command lists it, where you would look in the docs.
  • Apply the fix command (step 3), then verify (step 4).
  • Confirm status becomes Pulled.

Explain

  • Think of a navigator with no GPS. Saying 'I'm not certain of the exact flag, but here is how I would find it' still gets you to the destination and is trusted.
  • A simple loop: restate the symptom, give two or three ranked hypotheses, pick one check, say what each result would mean, then summarise the cause, fix and prevention.
  • If you are missing a fact, be honest in one short sentence, then show adjacent knowledge: which object owns it, which command lists it, where you would look in the docs.
  • If you realise mid-answer that you were wrong, correct yourself cleanly. That reads as senior, not weak.

Key points

  • Restate the problem first to buy thinking time.
  • Rank hypotheses before running checks.
  • Narrate what each check rules out.
  • Admit gaps in one sentence, then reason.
  • Never invent a flag or behaviour.
