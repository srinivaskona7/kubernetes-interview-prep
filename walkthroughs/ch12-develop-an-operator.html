⚠ Predicted failure

  • Pitfall: Skipping status updates, which leaves users blind to progress.
  • Pitfall: Giving the Operator cluster-admin.
  • If ignored, this surfaces as: NotEstablished.

✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • 1. Design: list functional needs (create and update Deployments, Services and ConfigMaps from the CR, report status) and non-functional ones (handle many CRs, recover from failures).
  • 2. Define the custom resource and its CRD schema. 3. Pick a framework and set up the toolchain; Go with the Operator SDK or Kubebuilder is the common route.
  • 4. Scaffold the project. 5. Write the controller and reconcile logic. 6. Use client libraries to create, update and delete child objects from CR state.
  • Apply the fix command (step 3), then verify (step 4).
  • Confirm status becomes Established.

Explain

  • 1. Design: list functional needs (create and update Deployments, Services and ConfigMaps from the CR, report status) and non-functional ones (handle many CRs, recover from failures).
  • 2. Define the custom resource and its CRD schema. 3. Pick a framework and set up the toolchain; Go with the Operator SDK or Kubebuilder is the common route.
  • 4. Scaffold the project. 5. Write the controller and reconcile logic. 6. Use client libraries to create, update and delete child objects from CR state.
  • 7. Build, test, generate manifests and ship, often as a container image plus a Helm chart or OLM bundle.

Key points

  • Operator SDK and Kubebuilder generate scaffolding and CRD manifests.
  • Test with envtest or a kind cluster before shipping.
  • Minimise RBAC to what the controller touches.
  • Package for distribution with Helm or OLM.
