⚠ Predicted failure

  • Pitfall: Forgetting the second label in the selector so the Service matches both versions
  • Pitfall: Deleting blue immediately after the switch
  • If ignored, this surfaces as: Progressing.

✓ Best troubleshooting path

  • Reproduce with the diagnostic command (step 1-2).
  • Imagine two identical stages in a theatre. The audience watches stage one while the crew rehearses on stage two; when ready, the spotlight swings over in one move.
  • In Kubernetes you create two Deployments whose Pods carry a version label, and one Service whose selector names the live version. Because the Service is just a label match, patching the selector moves all traffic at once.
  • The green side can be tested thoroughly, even with a separate test Service, before any real user touches it. The old blue Pods stay running, which is why rollback is nearly instant.
  • Apply the fix command (step 3), then verify (step 4).
  • Confirm status becomes Available.

Explain

  • Imagine two identical stages in a theatre. The audience watches stage one while the crew rehearses on stage two; when ready, the spotlight swings over in one move.
  • In Kubernetes you create two Deployments whose Pods carry a version label, and one Service whose selector names the live version. Because the Service is just a label match, patching the selector moves all traffic at once.
  • The green side can be tested thoroughly, even with a separate test Service, before any real user touches it. The old blue Pods stay running, which is why rollback is nearly instant.

Key points

  • Two environments, one active at a time
  • Cut-over is one selector change
  • Rollback is the same change in reverse
  • Requires roughly double the capacity during the release
  • Existing long-lived connections or sessions may be dropped at cut-over

Commands

CommandWhat it shows
kubectl apply -f blue-green-deployment.ymlCreate the app-blue and app-green Deployments
kubectl patch service my-app-service -p '{"spec":{"selector":{"app":"my-app","version":"green"}}}'Cut traffic over to green
kubectl patch service my-app-service -p '{"spec":{"selector":{"app":"my-app","version":"blue"}}}'Roll back to blue
kubectl get endpointslices -l kubernetes.io/service-name=my-app-serviceConfirm which Pod IPs the Service now targets
