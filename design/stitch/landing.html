High-Frequency Interview Question

Quick compare: Deployment vs StatefulSet vs DaemonSet

A standard favorite in Staff SRE and Kubernetes Platform interviews. Review the operational invariants below before answering.

Feature / Concept Deployment StatefulSet DaemonSet
Primary Use Case Stateless web APIs, microservices, asynchronous workers. Stateful clustered databases (Kafka, ZooKeeper, PostgreSQL, Elasticsearch). Node-level agents (Fluentbit, Node-Exporter, Promtail, CNI plugins).
Pod Identity & Naming Random hash suffix (e.g. api-7d49b-x92zk). Pods are fungible & interchangeable. Stable ordinal index (e.g. kafka-0, kafka-1). Persistent upon reschedule. Tied directly to the underlying Node name (one instance per matching Node).
Storage Binding Shared ReadWriteMany (NFS) PVC or ephemeral local emptyDir storage. volumeClaimTemplates generates dedicated PVC per ordinal pod index. Typically mounts the host filesystem using hostPath (/var/log, /proc).
Scaling & Ordering Concurrent and unordered creation/termination for maximum speed. Strict sequential order (0 → 1 → 2) or parallel via podManagementPolicy. Automatically scales up/down as new schedulable worker nodes join or drain.
Network Identity Shared Service VIP with round-robin traffic routing via iptables/IPVS. Requires a Headless Service (clusterIP: None) for dedicated DNS A-records. Often uses hostNetwork: true or direct hostPort mapping.
Rollout Strategy RollingUpdate with maxSurge & maxUnavailable knobs. RollingUpdate (in reverse ordinal order: N-1 to 0) or partitioned canary. RollingUpdate (controlled via maxUnavailable) or OnDelete legacy mode.
lightbulb
Interview Tip & Gotcha: When asked "Why does deleting a StatefulSet pod not delete its PVC?", explain that Kubernetes deliberately retains PVCs to avoid accidental data loss during crash loops. Deleting the volume requires manual human intervention or an explicit external controller policy.

psychology SCENARIO LAB #19 Networking Deep-Dive

"How does kube-proxy handle connection tracking and conntrack table saturation?"

When a cluster experiences high UDP traffic or microservice burst floods, the Linux Netfilter conntrack table can fill up, silently dropping new TCP SYN packets without emitting error logs inside application pods.

terminal Key Investigation Command:
sysctl net.netfilter.nf_conntrack_count sysctl net.netfilter.nf_conntrack_max
